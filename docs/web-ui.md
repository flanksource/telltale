# Web workspace

Run `telltale serve` after `make build`, then open the printed server URL. `make dev` uses the sibling Clicky UI source while production builds use the published dependency.

- **Connections** (`/connections`) lists the layered connection catalog. Add, edit, test, resolve, and delete workspace connections through the shared Clicky UI connection editor and its server-generated JSON Schema. Files in `./.connections` are writable; shared and application configuration layers remain read-only. Selecting a connection keeps its editor in `/connections/<id>` so it can be reopened directly.
- **Agents** (`/agents`) refreshes the connected agent inventory every five seconds. Each agent shows its runtime, resource attributes, labels, warnings, and advertised probes. **Arm capture** opens `/arm/<agent-id>/<probe>` with that agent and probe selected.
- **Arm captures** (`/arm`) uses the trace-start JSON Schema for the command, target, duration, capture parameters, and checkpoint interval. Starting opens the run in the overview; runs with a duration stop automatically, and an active run can also be stopped there. Probes without a corresponding server trace kind report an error before submission.
- **Query** (`/query`) selects a saved connection, with the selection in `/query/<id>`. The shared query workspace discovers the provider's catalog, completion, options form, structured query support, filters, and pagination. Query text is preserved in the `q` URL parameter. Execution errors are shown by the shared query browser.
- **Traces** (`/otel`) searches recorded SDK spans, recorded OpenSearch imports, spans the OTLP receiver received (the `receiver` run), or a saved OpenSearch/OpenTelemetry connection. The JSON Schema form filters by service, operation, trace ID, time window, status, exact span/resource tags, and whole-trace duration. Filters stay in the URL. Results open `/otel/<trace-id>` with a parent/child waterfall, collapse controls, error highlighting, and span/resource attributes; selecting a span adds `span` to the URL. Opening a trace retrieves all its available spans, including those outside the search window, and reports missing parents.
- **Trace records** open from a capture's **Open in query** link at `/records/<run>/<kind>/<stream>`. The page reads the kind's query profile for typed columns and filters, preserves the capture's sequence window, supports text search and a schema-driven form for a CEL row predicate and timestamp bounds, and pages with the server's continuation cursor. Export links continue to download the original trace format.

The UI uses `/api/v1/connection` for CRUD and schema negotiation (`Accept: application/schema+json`), `/api/v1/connections/dashboard` for inventory, `/api/v1/connection/<id>/browser` for query capabilities, `/api/agents` for agents, and `/api/traces` for capture runs. Trace queries use `/api/traces/<run>/traces/<kind>/records`; requesting its schema returns query options and columns derived from the result profile.

OpenTelemetry search uses `GET /api/otel`, with `/sources`, `/form`, and `/trace/<id>` for its catalog, schema, and full trace. Set `source=records` and optionally `run=<run-id>` (`run=receiver` for received spans), or use a connection ID from `/sources`. `tags` is a JSON object encoded as a query parameter. Search defaults to the last hour and 100 traces (maximum 1,000). Reads exceeding 100,000 spans fail explicitly: select a recorded run or narrow the OpenSearch window/index.

For OpenSearch, set the saved connection's `index`, `format` (`flat` or `jaeger`), and field mappings, or override the index/format in the form. OpenTelemetry connections reference an underlying OpenSearch connection. Jaeger documents use `startTimeMillis`, `traceID`, `spanID`, `process.serviceName`, `operationName`, and `CHILD_OF` references by default. OpenSearch imports are the `spans` kind's host seam (`run spans --seam host --opensearch-connection <name>`); `--opensearch-follow-index` keeps reading newly indexed spans, `--follow` prints captured rows, and `--opensearch-search` accepts a structured search JSON object.

Servers bound beyond loopback require API-scope authentication for these API routes, following the existing Telltale token policy.
