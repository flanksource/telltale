# Web workspace

Run `telltale serve` after `make build`, then open the printed server URL. `make dev` uses the sibling Clicky UI source while production builds use the published dependency.

- **Connections** (`/connections`) lists the layered connection catalog. Add, edit, test, resolve, and delete workspace connections through the shared Clicky UI connection editor and its server-generated JSON Schema. Files in `./.connections` are writable; shared and application configuration layers remain read-only. Selecting a connection keeps its editor in `/connections/<id>` so it can be reopened directly.
- **Agents** (`/agents`) refreshes the connected agent inventory every five seconds. Each agent shows its runtime, resource attributes, labels, warnings, and advertised probes. **Arm capture** opens `/arm/<agent-id>/<probe>` with that agent and probe selected.
- **Arm captures** (`/arm`) uses the trace-start JSON Schema for the command, target, duration, capture parameters, and checkpoint interval. Starting opens the run in the overview; runs with a duration stop automatically, and an active run can also be stopped there. Probes without a corresponding server trace kind report an error before submission.
- **Query** (`/query`) selects a saved connection, with the selection in `/query/<id>`. The shared query workspace discovers the provider's catalog, completion, options form, structured query support, filters, and pagination. Query text is preserved in the `q` URL parameter. Execution errors are shown by the shared query browser.
- **Traces** (`/otel`) searches recorded SDK spans, recorded OpenSearch imports, spans the OTLP receiver received (the `receiver` run), or a saved OpenSearch/OpenTelemetry connection. The JSON Schema form filters by service, operation, trace ID, time window, status, exact span/resource tags, and whole-trace duration. Filters stay in the URL. Results open `/otel/<trace-id>` with a parent/child waterfall, collapse controls, error highlighting, and span/resource attributes; selecting a span adds `span` to the URL. Opening a trace retrieves all its available spans, including those outside the search window, and reports missing parents.
- **Trace records** open from a capture's **Open in query** link at `/records/<run>/<kind>/<stream>`. The page reads the kind's query profile for typed columns and filters, preserves the capture's sequence window, supports text search and a schema-driven form for a CEL row predicate and timestamp bounds, and pages with the server's continuation cursor. Export links continue to download the original trace format.

The UI uses `/api/v1/connection` for CRUD and schema negotiation (`Accept: application/schema+json`), `/api/v1/connections/dashboard` for inventory, `/api/v1/connection/<id>/browser` for query capabilities, `/api/agents` for agents, and `/api/traces` for capture runs. Trace queries use `/api/traces/<run>/traces/<kind>/records`; requesting its schema returns query options and columns derived from the result profile.

Trace definitions are served under `/api/traces/definitions`; a write takes only a same-origin request:

- `GET /api/traces/definitions` lists each definition in effect as `{name, layer, path, resourceVersion, description, counts: {proxy, instrument, collect}, problem?}`, `layer` one of `cwd`, `global` or `builtin`, `problem` the load error of an unreadable file.
- `GET /api/traces/definitions/schema` is `{schema, lists, layers}`: the CRD's `openAPIV3Schema` for the editor's form, every typed list (`{path: "collect.prometheus.scrape", section, group, type, kind, title, description}`) for its "add capture" menus, and the layers (`{name, writable, dir}`) it can save to.
- `GET /api/traces/definitions/<name>` is `{name, layer, path, resourceVersion, definition, yaml, entries}`: the definition as JSON, its file's text, and each entry as `{pointer, path, kind, name, defaultName, connection}`, `connection` being the one it names or the default it takes. An unknown name is a 404, an unreadable file a 422.
- `POST /api/traces/definitions/validate` takes `{definition}` (JSON, or the YAML as a string) and answers 200 `{errors: [{instancePath, message}], entries}` from static validation, so the editor shows default names and errors as it is edited; a body that does not decode is a 400.
- `PUT /api/traces/definitions/<name>` takes `{layer, resourceVersion, definition}`, with `resourceVersion: ""` to create and `definition.metadata.name` equal to `<name>`. It answers as the `GET`; 409 `{error, resourceVersion}` with the file's current version when it exists or changed since read; 400 `{name, errors}` for an invalid definition or the read-only `builtin` layer.
- `DELETE /api/traces/definitions/<name>?layer=&resourceVersion=` answers 204, 409 when the file changed since read, and 404 when the layer does not have it.
- `POST /api/traces` with `{definition: "<name>", command?, pid?, duration?, every?}` starts a run of a stored definition and answers as an ad-hoc start; naming `traces` too is a 400. The run's `definition` (`{name, resourceVersion, spec}`, the spec as resolved) is in its listing and `run.json`.

OpenTelemetry search uses `GET /api/otel`, with `/sources`, `/form`, and `/trace/<id>` for its catalog, schema, and full trace. Set `source=records` and optionally `run=<run-id>` (`run=receiver` for received spans), or use a connection ID from `/sources`. Filters match whole traces: `services` (any span's service), `operations` (the root operation), `statuses` (`error` when a span failed, else `ok`) and `attributes` (any span's attribute as `key`, `key=value` or `key=prefix*`) are each a JSON object of value to `include` or `exclude`, encoded as a query parameter; includes are any-of (attributes: any-of per key, all-of across keys) and excludes reject. `minSpans` keeps traces of at least that many spans. Besides the newest traces, a search returns `rootOperations`, the window's traces counted by root operation with p50/p95 durations (every filter applied but `operations` and `minSpans`), and `attributes`, frequent root-span `key=value` suggestions. Search defaults to the last hour, 100 traces (maximum 1,000) and, from the `/form` defaults the page uses, `minSpans=2`.

The `/otel` page puts these filters on one bar: **Received** (the receiver run) or **Recorded** spans or a connection, service, root operation, attributes, status, a duration range, **Hide single-span traces** and the time window. It searches as filters change, keeping the previous results dimmed under an elapsed timer with **Cancel**. Beside the results, the root operations list counts and p50/p95 for the window and filters to one with a click; above them, a duration-over-time scatter opens a trace from its dot. **Jump to trace ID** opens a trace by its 16- or 32-hex-character ID. Reads exceeding 100,000 spans fail explicitly: select a recorded run or narrow the OpenSearch window/index.

For OpenSearch, set the saved connection's `index`, `format` (`flat` or `jaeger`), and field mappings, or override the index/format in the form. OpenTelemetry connections reference an underlying OpenSearch connection. Jaeger documents use `startTimeMillis`, `traceID`, `spanID`, `process.serviceName`, `operationName`, and `CHILD_OF` references by default. OpenSearch imports are the `spans` kind's host seam (`run spans --seam host --opensearch-connection <name>`); `--opensearch-follow-index` keeps reading newly indexed spans, `--follow` prints captured rows, and `--opensearch-search` accepts a structured search JSON object.

Servers bound beyond loopback require API-scope authentication for these API routes, following the existing Telltale token policy.
